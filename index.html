BEAT 08 · BUILT LIKE A PRODUCT, NOT A HOMEWORK ASSIGNMENT

The parts you only appreciate when things break.

🛡 The AI engine

prompt → JSON mode (temp 0.3) → REST + SDK fallback → Zod parse

Dual-path with 20s aborts and candidate Flash models. Scores labeled "AI estimate". The coach refuses to invent facts or promise outcomes — and redirects legal questions to official sources.

🔐 Zero-trust security

firestore.rules → allow read, write: if false

The browser cannot touch data — everything flows through the authenticated Admin SDK. 5-day httpOnly · secure · SameSite session cookies, minted only if sign-in is <5 min old. 0 keys in the browser.

🧹 Privacy + fair use

resumes/{uid}/ · path-traversal blocked · timingSafeEqual cron

Resumes live in a private B2 bucket and self-destruct in ~1 hour (cron 17 3 * * *). Daily quotas in Firestore transactions: 100 chats · 5 resume scans · 10 interviews · 60 answers · 5 job refreshes.

🗂 Data model

users/{uid} → careers/{id} → skillGap · roadmap · projects · opportunities

Plus resumes · interviews · chat · notifications · usage/{date} · communityPosts. Atomic batches + transactions — concurrent clicks can't double-count, and the usage ledger powers quotas with zero extra infrastructure.

⏳ Reliability

retry 1s → 2s → 4s (cap 6s) · healthz poll 30s / 6s

Graceful degradation everywhere: saved matches survive AI outages, writes race 3–4s DB timeouts so responses never hang, ImgBB falls back to data URIs, Remotive capped at 12s. A failed feature is a notice, never a broken app.

⚙ Types & deploy

openapi.yaml → Orval → Zod + typed React-Query hooks

Even Gemini's output passes the same validation — bad AI data dies at the border. Deploys to Vercel: static edge + one serverless function (60s), daily cron, /api/healthz + /api/ai/diagnose observability.
