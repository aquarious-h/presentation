Security & Privacy — paranoid by design.

🔐 Zero-trust database

Firestore rules: allow read, write: if false — the browser cannot touch data. Every read/write flows through the authenticated Admin SDK on the server.

🍪 HTTP-only sessions

5-day session cookie: httpOnly · secure · SameSite=Lax. Minted only if your sign-in is <5 minutes old. JS can't steal what it can't read.

🔑 Secrets never ship

Gemini key, B2 keys, ImgBB key, service account — server env vars only. Stat from earlier: 0 keys in the browser, verified.

🧹 Resumes self-destruct

Private B2 bucket · path-traversal blocked (resumes/{uid}/ prefix + .. checks) · auto-deleted ~1h by cron guarded with timingSafeEqual secret comparison.

🚦 Fair-use quotas

Per-user daily limits in Firestore transactions: 100 chats · 5 resume scans · 10 interviews · 60 answers · 5 job refreshes. No runaway bills, no abuse.

🧾 Input hygiene

Zod on every payload · filename sanitization · HTTPS-only image URLs · PDF magic-byte checks · comment/post length rules · ID format regex.

ACT III · THE ENGINEERING

Reliability — built for the day everything breaks.

Graceful degradation

AI fails? Your saved matches stay untouched. DB slow? Writes race a 3–4s timeout so responses never hang. ImgBB down? Avatars fall back to inline data URIs. Nothing takes the whole app down.

Self-healing client

Retries with exponential backoff (1s → 2s → 4s, capped at 6s). Health endpoint polled every 30s — 6s while unhealthy — and the dashboard auto-refetches the moment the API breathes again.

Backpressure everywhere

12s timeout on Remotive, 20s per model attempt on Gemini, 300s TTL on upload URLs, batched deletes (5 at a time, 25 per cron run) — the system protects itself and its providers.

Design rule: a failed feature is a notice, never a broken app.
